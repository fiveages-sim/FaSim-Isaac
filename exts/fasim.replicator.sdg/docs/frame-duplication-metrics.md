# 数据质量判据：为什么"图像重复"不能看全图均值

日期：2026-11-12
结论：**sdg 与同事的数据都没有重复帧。** 我一度误判为 45.7% / 72.8% 重复，
根因是用了错误的判据。这里记录正确方法。

---

## 1. 错误判据（我之前用的）

```python
diff = np.abs(cur.astype(np.float32) - prev.astype(np.float32))
if diff.mean() < 0.5:
    dup += 1        # ← 错在这里
```

结果：

| 数据 | mean\|diff\| < 0.5 的比例 | 判定 |
|---|---|---|
| 同事 base_0_rgb（1280×720） | **68.8%** | 误判"重复" |
| 同事 left_wrist（640×480） | **66.0%** | 误判"重复" |
| sdg run_04 head（640×480） | **49.5%** | 误判"重复" |

### 为什么错

机器人只占画面一小块（实测变化像素占比中位数 **0.1%~0.8%**），
其余 99% 是静态背景（桌面、架子、墙）。全图 64 万像素求平均，
几百个像素的变化被稀释成 0.5 以下的均值。

**这是分析静态场景视频的经典陷阱**：均值对"稀疏但真实的局部变化"极不敏感。

---

## 2. 正确判据

### 2.1 最硬判据：逐位相同

```python
if np.array_equal(cur, prev):   # 整个数组 bit 级相同
    dup += 1
```

真重复帧一定是逐位相同（同一个缓冲区内容）。
反之只要有 1 个像素差 1，就不算重复。

### 2.2 辅助判据

| 判据 | 含义 | 阈值建议 |
|---|---|---|
| `diff.max() == 0` | 有任何像素变化吗 | 硬判据 |
| `(diff > 8).mean()` | 明显变化的像素占比 | 看量级，别卡阈值 |
| `(diff > 0).mean()` | 有任何变化的像素占比 | 同上 |
| `diff.mean()` | **只作趋势参考，不要用来判重** | 不要卡 0.5 |

---

## 3. 复核结果（2026-11-12）

### sdg run_04（651 帧，head_rgb 640×480）

| 判据 | 结果 |
|---|---|
| **逐位相同** | **0 / 650 = 0.0%** |
| `max == 0` | 0 / 650 = 0.0% |
| `mean < 0.5`（错误判据） | 322 / 650 = 49.5% |

```
mean     : min=0.0539  med=0.5282  max=5.5315
max      : min=5.0000  med=125      max=219
frac_gt8 : med=0.0084  max=0.1266
frac_gt0 : med=0.2216  max=0.5829
```

**关键：`max` 的最小值是 5** —— 每一对相邻帧至少有像素差 5，
说明每帧都是新图。`frac_gt0` 平均 22% 像素在变，是真实的机器人在动。

### 同事 base_0_rgb（2257 帧，1280×720）

| 判据 | 结果 |
|---|---|
| **逐位相同** | **0 / 2256 = 0.0%** |
| `max == 0` | 0 / 2256 = 0.0% |
| `mean < 0.5`（错误判据） | 1552 / 2256 = 68.8% |

```
mean     : med=0.1468  max=2.792
max      : med=36      min=2
frac_gt8 : med=0.001  p95=0.030
```

同样是 0 重复。`max` 中位数 36，每帧都在变。

### 为什么同事的 `mean` 更低

两件事叠加，**都不是问题**：

1. **分辨率更高**（1280×720 vs 640×480）：变化像素占比相同时，
   像素总数多 3 倍，但变化像素也被摊到更多像素上 → 均值更低。
   实际 `frac_gt8` 中位 0.1% vs 我们的 0.84% —— 他们机器人占画面比例更小
   （视角更远/视野更宽）。
2. **H.264 压缩**：视频编码会平滑掉细微差异，`max` 中位 36（我们 125）。
   这是有损压缩的正常代价，不是数据缺陷。

> 注意：如果将来要查"视频编码是否吃掉有效信息"，应该比 `frac_gt8` 和
> 视觉检查（`sdg.sh shots`），而不是比 `mean`。

---

## 4. 关于 `sdg.sh shots`

`camera_shots.py` 用 `np.linspace` **均匀抽样**（默认 8~16 张）生成联络图。
均匀抽样跨过的是几十上百帧，**天然不会抽到相邻帧**，所以：

- ✅ 用 shots 看"整体轨迹是否在动"——有效
- ❌ 用 shots 判断"相邻帧是否重复"——**无效**（抽样间隔太大）

判断重复必须遍历全部相邻帧，不能用抽样图。

---

## 5. 复现脚本

正确的检查方法（遍历全部相邻帧 + 多重判据）：

```python
prev = None
for f in sorted(session.glob("frames/frame_*.npz")):
    with np.load(f) as z:
        cur = z["head_rgb"]
    if prev is not None:
        d = np.abs(cur.astype(np.int16) - prev.astype(np.int16))
        print(f"exact={np.array_equal(cur, prev)} "
              f"max={d.max()} frac_gt8={(d>8).mean():.4f} mean={d.mean():.3f}")
    prev = cur
```

## 6. 教训

1. **别用标量均值判断稀疏变化**。图像里机器人占比小、背景大，
   均值会被背景主导。用 `max` / `frac_gt*` / 逐位比较。
2. **"看起来一样"和"数据相同"是两件事**。静止时图像帧逐位相同是
   **正确的**（场景没变）；运动时必须不同。
3. **抽样图不能用来查重复**，只能看整体。
4. 我基于错误判据改动过采集架构（加 `capture_mode=render`），
   复核后已全部回滚 —— 原实现（物理步回调 + 渲染 tick 驱动）
   本来就是对的，注释里"实测 33/33 帧互不相同"也是对的。
